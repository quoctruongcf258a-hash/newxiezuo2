## 2026-10-10 新增：环节0「已有项目」继续入口（跳过初始化/梗概，直接进环节1 续作）

### 背景 / 目的
用户反馈：每次启动 CollabApp 都会进入「环节 0 · 项目初始化」，重新填写表单并生成**新的项目名**，
无法回到之前未完成的项目继续进度。新增「已有项目」选择组，选中历史项目后一键加载并跳到中央区环节1（规划），
沿用原项目的产出目录、工作区与运行状态，免去重复初始化。

### 改动文件清单
1. `app/collab_app.py`
   - `_build_stage0_widget`：在标题/提示下方、tabs 之前新增「已有项目（继续未完成的进度）」组，
     含 `self.existing_combo`（下拉，启动时由 `_fill_existing_projects` 填充有效项目）+ 「↻」刷新 + 「继续项目」按钮。
   - 新增 `_fill_existing_projects()` / `_list_existing_projects()`：列出 `OUTPUT/<项目名>/` 下含 `00_初始化` 的有效项目。
   - 新增 `_on_continue_project()`：读取所选项目 → 设置 `self._proj_ws/_proj_name` →
     `paths.set_active_project_workspace(workspace/<项目名>)` → 从 `00_初始化/项目信息.json` 读回章节数并同步给 `auto_stage`
     （`set_chapter_count/set_current_chapter/set_project_workspace/save_chapter_progress`）→
     `stack.setCurrentIndex(2)` + `tabs.setCurrentIndex(0)` 直接进中央区环节1 →
     `_refresh_all_panels()`（AssignPanel.refresh 会从激活工作区重载 state/run_state，**保留之前门控/进度，不重置**）。

### 接线 / 联通关系
- 有效项目判定：产出目录 `output/<项目名>/00_初始化` 存在即视为可继续（与新建项目目录结构一致）。
- 进度还原关键：`AssignPanel.refresh()` 每次都 `sb.load()` 读激活工作区，故先 `set_active_project_workspace` 再刷新即可还原。
- AI 指派仍是全局 `rules/assignments.json`，跨项目共用（环节 key 一致），无需按项目隔离。

### 回退方式
- 删除 `app/collab_app.py` 中「已有项目」组构建代码（约 `_build_stage0_widget` 内 `exist_box` 一段）、
  `_fill_existing_projects`/`_list_existing_projects`/`_on_continue_project` 三个方法即可回到纯新建流程。
- 逻辑无副作用：未选「继续项目」时与普通新建流程完全一致。

## 2026-10-10 新增：环节终审闭环（审核者/调整者 = 整合总结 + 打钩清单 + 复审迭代 + 强制本地端）

### 背景 / 目的
用户要求：每个大环节最后的「审核者 + 调整者」不再只是打分和改稿，而要承担**环节终审闭环**：
1. 把当前大环节**所有产出整合总结**；
2. 审核者输出「打钩清单」式弊病表（`- [x]` 达标 / `- [ ]` 未达标）；
3. 调整者按未打钩项逐条修改，**改完必须再交审核者复审**；
4. 只有审核清单**全部打钩**，调整者才交付；
5. 审核者/调整者**只能是本地运行（非 web）的 AI**。

改造前的问题：审核/调整是「一次性线性」的（审核→调整→结束），终审子步根本没有调整者，
评审材料只汇总本子步的块（`_assemble_step_material`），也不做任何打钩判定。

### 改动文件清单
1. `prompts/**`（生效目录 `C:\mai\multi-ai-pipeline\prompts`，与 `AI指派协作\prompts` 备份一致）
   —— 为各环节审核者/调整者提示词追加「环节终审闭环」章节（幂等，标记段落重复运行不叠加）：
   - 审核者：`01_规划/_审核者.md`、`02_写作/2-3_审核.md`、`02_写作/2-5_终审放行评审.md`、
     `03_去AI/_审核者.md`、`04_审核/_审核者.md`、`05_出厂/_审核者.md`
     → 追加「整合总结 + 打钩清单 + 结论（全部打钩方可交付）」。
   - 调整者：`01_规划/_调整者.md`、`02_写作/2-4_调整.md`、`03_去AI/_调整者.md`、
     `04_审核/_调整者.md`、`05_出厂/_调整者.md`
     → 追加「整合总结 + 按清单逐条改 + 修改对照表 + 交复审 + 全打钩才交付」。
2. `app/auto_stage.py`（核心）
   - `_review_path` / `_adjust_path` / `_item_artifact_path` 新增 `round` 参数：
     第 1 轮沿用 `X_审核意见.md`/`X_调整稿.md`；第 N≥2 轮为 `X_审核意见_第N轮.md`/`X_调整稿_第N轮.md`。
   - 新增常量与工具：`FINAL_LOOP_MAX_ROUNDS=3`、`REVIEWER_LOCAL_ONLY`、`ADJUSTER_LOCAL_ONLY`、
     `last_step_name()`、`assemble_stage_material()`（汇总本环节全部块产出+调整稿）、
     `loop_round()/set_loop_round()`（轮次存于 `rstate["stages"][sk]["loop_rounds"][sn]`）、
     `review_all_checked()`（打钩判定）、`local_ais_names()`、`local_role_guard()`。
   - `review_all_checked` 判定顺序：有 `- [ ]` → 未通过；全 `- [x]` → 通过；
     无清单时回退结论句（全部打钩/全部通过/无弊病/无需修改/可交付）；都没有 → 判未通过（保守）。
   - `_review_prompt`/`_adjust_prompt` 前置 `_loop_head(role, round)`：注入「整合总结 + 打钩清单 +
     交复审」指令；round≥2 追加「第 N 轮复检：对照上一轮清单逐条复核」。
   - `_run_step`：最后一个子步（`is_stage_final`）改用 `assemble_stage_material` 作为评审材料；
     审核/调整改为 `_run_review(rnd)` / `_run_adjust(rnd, rev)` 两个可复用的轮次函数；
     adjuster 完成后进入 `while` 闭环——未全部打钩则 bump 轮次、重置 reviewer/adjuster 状态、
     重跑审核复审 + 调整者再改，直到全打钩或达 `FINAL_LOOP_MAX_ROUNDS`（达上限则日志告警请人工确认）。
   - `_ordered_items`：去掉 `not final` 条件，**终审子步也纳入 `adjuster`**（否则无法闭环）。
   - `run_next_item`（手动模式）：开头检测最后一个子步「审核+调整已通过但未全部打钩」→ 开启下一轮
     复检并把 reviewer/adjuster 状态重置为 `none`；上下文与产物路径按 `loop_round()` 解析；
     审核/调整发送前走 `local_role_guard`。
   - `_prompt_template_path`：终审子步 reviewer 的 glob 增加 `*终审*.md` 前缀优先级，
     修复「写作/终审」落到 `2-3_审核.md` 的问题（现正确命中 `2-5_终审放行评审.md`）。
3. `app/stage_board.py`
   - `_step_items`：终审子步也返回 `["reviewer","adjuster"]`（原来 final 只返回 reviewer）。
   - `local_ais()`：优先返回「已启用」的本地端，全部未启用才退回全部本地端。
4. `app/collab_app.py`（`_generate_project_plan` 预指派）
   - 新增 `role_pool = local`（本地端池）；审核者/调整者固定从 `role_pool` 取，终审子步同样指派调整者。
   - 日志区分「产出块池」与「审核者/调整者池」。
5. `app/assign_panel.py`
   - 新增 `self.role_ais`（本地端候选池）与 `_combo_role()`：审核者/调整者下拉**只列本地端 AI**。
   - 终审子步 UI 增加「调整者」行（原来只有「终审放行评审」）。
   - `set_ais()` 刷新时，block 下拉用全量池、role 下拉用本地端池。

### 接线关系
```
每个大环节最后一个子步（环节终审）
  材料：auto_stage.assemble_stage_material() ← 本环节所有块产出 + 已有调整稿
  角色：state[sk]["steps"][sn]["reviewer"/"adjuster"]
        ← 预指派 collab_app(role_pool=local) / UI assign_panel._combo_role(role_ais=本地端)

  轮次：rstate["stages"][sk]["loop_rounds"][sn]（1..FINAL_LOOP_MAX_ROUNDS）
  产物：<子步>_审核意见[_第N轮].md / <子步>_调整稿[_第N轮].md
  闭环：审核 → 调整 → review_all_checked?  否 → 下一轮复审+再改；是 → 调整者交付
```

## 2026-10-10 修复：本地/WEB 判定错位 + 第0环节规划仅限本地端

### 背景 / 目的
初始化预指派时，`local_ais()` 一直返回空，导致「本地优先」退化成「全回退网页端」。
根因：运行时发信用的是 `rules/ai_apps.json`（即『添加AI』对话框写入的那份，含正确

`type:"web"`，且命名都对不上（如 rules 里的 `小张同学`/`千问` 在那份叫 `deepseek`/`tongyi`）。
于是本地检测永远为空。

用户明确：本地/WEB 区分应以『添加AI』当时选的为准；且**只有本地端才能承担第0环节『规划』**
（网页端无法自写文件，规划蓝图需本地端落盘）。

### 改动文件清单

   - `local_ais()`：`类型 == "electron"` 即本地端（不再读错位的 windows-use/apps.json）。
   - `available_ais()`：返回 `启用 != False` 的 AI 名（含本地 + 网页），与 mix_send 实际
     可投递的 AI 完全一致（修复了旧 selected 名字在 mix_send 里查不到 CDP 端口的隐患）。
2. `app/collab_app.py` —— `_generate_project_plan` 预指派逻辑：
   - 第0环节「规划」(`sk == "规划"`) **只能**派给 `local_ais()` 返回的本地端；
     若无本地端，打印警告并跳过该环节指派，提示先在『添加AI』选本地端后重跑初始化。
   - 其余环节：保持「本地优先，无本地则回退已选 AI 池（网页端）」。

### 接线关系
`players.load_players()`(rules/ai_apps.json)  ← 添加AI对话框写入（类型/启用）
        ├─ mix_send._lookup / _type_of（发送 + web/electron 区分）【原本就正确】
        ├─ auto_stage._is_web（发送分支判断）【原本就正确】
        └─ stage_board.local_ais / available_ais（本次改为读这里）【修复】

  Qianwen、ZCode、ima、gemini。
- `available_ais()` 返回启用池（网页 + 启用的本地），全部是 mix_send 可解析的名字。
- `py_compile` 通过；已 restart_collab 重启生效。

## 2026-10-10 新增「手动模式」：断开全自动，改为逐块手动发送

### 背景 / 目的
每个子环节原默认「启动」即全自动连续跑完（块→审核→调整→下一个块…）。用户要先全手动跑一轮、逐步核对，跑通后再恢复全自动。
因此新增一个**手动模式开关**：勾上后断开「启动」全自动，改为点「发送下一个子项」逐块发送，严格串行、上下文累加。

### 改动文件清单
1. `app/auto_stage.py` —— 执行引擎，新增手动发送核心函数。
2. `app/collab_exec.py` —— 薄封装 re-export，导出新函数。
3. `app/assign_panel.py` —— UI 面板，底部加勾选框与按钮。
4. `app/collab_app.py` —— 宿主主窗口，加后台线程与宿主方法。
（源码 `c:/mai/multi-ai-pipeline/app` 与运行副本 `AI指派协作/app` 均已同步。）

### 接线关系（联通图）
手动链路（新增，蓝色为新增节点）：

```
UI 底部「☐ 手动模式」勾选框 (AssignPanel.manual_cb)
   └─ stateChanged → AssignPanel._on_manual_toggle(state)
        设置 self.manual_mode
        调 _refresh_gates() + set_start_enabled(True)
          → 手动模式: 禁用 start_btn(全自动)、启用 next_btn(发送下一个子项)

UI 底部「▶ 发送下一个子项」按钮 (AssignPanel.next_btn)
   └─ clicked → AssignPanel._on_next()
        校验未指派 → 先 _lock_start()(防重复点击)
        调 self.manual_next_callback(sk)   # 宿主在 _build_collab_central 里挂上

collab_app._run_collab_next_item(sk)   # 宿主方法 = 复制 _run_collab_stage 前置
   前置: dry 标志、set_project_workspace、load_chapter_progress、
         verify_chapter_from_disk(当前章)、写作环节 reset_chapter_cycle()
   防重复: 若 _stage_worker 或 _next_worker 仍在跑则忽略
   起 _StageNextWorker(sk, dry, chapter)

collab_app._StageNextWorker(QThread)
   └─ run(): collab_exec.run_next_item(...)   # 后台执行，不冻 UI

collab_exec.run_next_item → auto_stage.run_next_item(stage_key, log_fn, dry, refresh_fn, chapter)
   1) _ordered_items(stage_key) 取本环节全部子项顺序 [(step,type,key)]
   2) 找下一个 item_status != "pass" 的子项；要求它前面所有子项都已 pass（否则报错不发）
   3) 构造上下文 = 上游累积稿(_upstream_text) + 本环节此前已通过子项的产物(累加)
      （章意识环节再叠加 _chapter_upstream：上一章 + 上一环节同章待处理稿）
   4) 按 type 分别:
        block  → _block_prompt  + _do_task → _produce_path
        reviewer→ _review_prompt + _do_task → _review_path
        adjuster→ _adjust_prompt(带审核意见) + _do_task → _adjust_path
   5) _finalize_item(): 空/非真实文件 → cascade_fail_from_item 返回 False；
                        否则 set_item_status(pass) 返回 True
   6) 每次写盘/改状态后 save() 并通过 refresh_fn 实时刷新 UI 圆点

collab_app._on_next_done(ok, msg)   # 线程 done 信号
   对所有面板 _unlock_start()(重新点亮 next_btn)；_refresh_all_panels()；日志提示
```

### 手动模式 vs 全自动 的切换机制
- `AssignPanel.manual_mode` **默认 False** → `start_btn` 启用、`next_btn` 禁用 → **全自动照常**（未破坏原链路）。
- 勾选 `manual_mode=True` → `start_btn` 禁用（全自动断开）、`next_btn` 启用 → 逐块手动。
- 取消勾选 → 立即恢复全自动。

### 原全自动链路（完整保留，未改动逻辑）
```
「启动」按钮 → AssignPanel._on_run → panel.run_callback
   → collab_app._run_collab_stage(sk)
   → _StageRunWorker(QThread) → collab_exec.run_stage → auto_stage.run_stage
```

### 如何「回头重连全自动」
1. **最简单（推荐）**：在面板上取消勾选「手动模式」即可，全自动原样可用；手动模式代码可保留（默认关闭、无害）。
2. **若想彻底删除手动模式**：
   - `assign_panel.py`：删 `manual_cb`、`next_btn` 及其创建代码；删 `_on_manual_toggle`、`_on_next`；
     在 `_lock_start/_unlock_start/set_start_enabled/set_assign_mode/_refresh_gates` 中删去所有
     `manual_mode`、`next_btn` 分支；删实例属性 `manual_mode`、`manual_next_callback`。
   - `collab_app.py`：删 `_StageNextWorker`、`_run_collab_next_item`、`_on_next_done`；
     删 `_build_collab_central` 里的 `panel.manual_next_callback = ...` 赋值。
   - `collab_exec.py`：从 import 列表与 `__all__` 删 `run_next_item`。
   - `auto_stage.py`：删 `_ordered_items`、`_finalize_item`、`run_next_item`。

### 关键约束（手动模式行为）
- 严格**串行**：必须等前一个子项真正落盘且通过，才发下一个。
- **上下文累加**：下一个子项的提示词自带前面所有已通过子项的完整产出，天然综合参考。
- **前序未通过不发下一项**：跳过会导致上下文错乱，已在 `run_next_item` 内校验拦截。
- 重跑某子项：点它右侧 ✖ 红钮作废旧产物（item_status 置 fail/重置），再点「发送下一个子项」从该子项重发。
- 全部子项通过（全绿）后「放行」按钮才亮，放行进下一环节。

## 2026-10-10 让 `_logs` 真正用起来：运行日志落盘 + 产物文件树清单 + 第0步梗概文件

### 背景 / 目的
`_logs` 目录此前只是 `TREE` 里的空占位，从不写入。本次把它接上实际用途，方便**按项目回溯**每次运行的产出与日志。

### 改动文件

### 三处改动
1. **运行日志真正落进 `_logs`**：`log_line()` 现在在写界面日志的同时，把每条日志带时间戳追加写入 `<项目>/_logs/run_YYYYMMDD.log`。因为所有 worker 的 `progress` 信号都连到 `log_line`，所以全自动 / 手动 / 环节1 / 写作等全部运行输出都会被捕获，按天分文件。
2. **产物文件树清单落到 `_logs`**：新增 `_write_tree_manifest(tag)`：遍历项目产出目录（排除 `_logs` 自身，避免自我递归），列出每个文件的相对路径 / 大小 / 修改时间，写入 `<项目>/_logs/文件树清单_<tag>_<时间戳>.json`。在以下时机自动生成：

   - 手动模式每发完一个子项（`_on_next_done`，tag = 该环节 key）；
   - 步骤0 梗概落盘后（`_on_wb_captured`，tag = "步骤0"）。

### 回溯方式
- 日志：`<项目>/_logs/run_YYYYMMDD.log`（按天累积，含全部运行输出，含 worker 后台输出）。
- 清单：`<项目>/_logs/文件树清单_*.json`（每次环节 / 子项 / 步骤0 完成各一份，可看当时产物快照）。
- 第0步梗概：`<项目>/00_初始化/第0步梗概.md`。

- 不要清单：删各回调里的 `self._write_tree_manifest(...)` 调用及 `_write_tree_manifest` 方法。

## 2026-10-10 运行时读取规划 + 按产出要求校验 + 指派面板「查看规划」按钮

### 背景 / 目的
上一节只在初始化生成了规划蓝图（`workspace/<项目>/规划/*.md`）。本节把规划真正接入运行时：子步执行前引用规划契约、完成后对照规划的「产出要求」校验产物是否被规划列出（漂移检测）；并在指派面板每个子步加「📋 查看规划」按钮，一键打开对应规划文件。

### 改动文件
1. `app/auto_stage.py` —— 新增规划契约助手，并在 `_run_step`（自动）/`_finalize_item`（手动）注入「执行前读规划 + 完成后对照校验」。
2. `app/collab_app.py` —— 修正 `_build_step_plan` 章意识环节文件名（之前用 `chapter=None` 生成了带 `2-1_` 索引前缀的错误名；现改为与运行时一致：`第{N}章_<块>.md`）；新增 `_open_plan_file` 并挂载给面板回调。
3. `app/assign_panel.py` —— 每个子步加「📋 查看规划」按钮，点击经 `open_plan_callback` 调宿主打开对应规划文件。
（源码 `app/` 与运行副本 `AI指派协作/app/` 均已同步。）

### 接线关系（联通图）
```
auto_stage：
  _run_step(stage, step, ..., chapter)            # 自动模式（run_stage/run_all 都走它）
    └─ 子步开始：if _plan_file_for(stage, sn) 存在 → log「📋 执行前读取规划契约：<path>」

  _finalize_item(...)                             # 手动模式（run_next_item 走它）
    └─ 通过后同样 _plan_file_for + 漂移警告
```

### 关键设计
