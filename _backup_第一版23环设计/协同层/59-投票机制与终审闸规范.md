# 59 · 投票机制与四道终审闸

> 本文件由 `scripts/export_newskill.py` 从 apps.json / roster.json 自动生成，请勿就地手改；改配置后重跑脚本。

终审投票机制（用户最新裁定）：不要每个 AI 都出完整大纲/完整成书——按块切分产出；汇总者筛最优一版拼成候选汇总稿；全员对候选稿终审投票，过半通过才进下一大环节；平票则交叉提意见+综合改稿再投。


## 一、分块产出（不要求各出完整稿）

- **mode**：chunked
- **rule**：不要求每个 AI 各出完整版。环节按块切分（章纲按章切 / 设定按子项切 / 正文按六要素段切 / 润色按节切 / 质检按维度切），每个 AI 认领或被分配若干块；关键块可让多个 AI 同块赛马，其余块单写即可。

## 二、汇总择优

- **by**：merge_app（可换）
- **rule**：汇总者读全部分块产出 + 全部评审，按块筛最优一版拼成『候选汇总稿』（不逐块打分给分，只做择优选择：一致好评取之，否则多数票胜出，全差则退回该块重写）

## 三、终审投票

- **voters**：全员 N（含写过块的与没写过的，全部参与终审）
- **ballot**：通过 / 不通过 + 具体意见；每张反对票必须附『问题定位卡』四件套（①出在哪 ②哪一条标准 ③正文关键句＋检索词 ④修改建议），四件套缺件不计票，退回补全
- **passRule**：赞成 > N/2（过半通过）→ 进入下一个大环节
- **failRule**：赞成 < N/2（未过半，非平票）→ 回退：把不通过意见按块归类，打回对应块补做重写，重写后再投
- **tieRule**：赞成 == 反对（平票，N 为偶数时出现）→ 交叉提意见 + 综合改稿：让赞成分与反对方互提意见（各自说清『我为什么通过/不通过、对方哪点没考虑到』），由 merge_app 做综合改稿吸收双方意见，改完再投一轮
- **maxRounds**：2
- **onMaxRounds**：达到上限仍不过半 → 转为人工裁决（人拍板取哪一版或指定重写范围）

## 四、盲审隔离

- **enabled**：True
- **rule**：分块评审阶段仍遵守盲审隔离：每位评审新建独立对话、不看他人草稿与评审、只审分配给自己的块

## 五、四道终审闸明细

### 规划 · 章纲终审
- 位置：规划程序出口（写作开始前）
- 执行处：规划验收
- 投票人：全员 N
- 通过规则：过半通过
- 校验项：
  - 八方向审核标准全过（auditDirections 72 条）
  - 前30章章纲齐备且含六要素阶段字段
  - 设定/人物/伏笔表无矛盾
  - 能直接进正文
- 番茄专属校验项：
  - 番茄立项核查：类型落在番茄主力品类或 2026 趋势赛道内
  - 书名备足 ≥5 个（20—50 万字与 100 万字书测各需提交 5 个）
  - 书名含品类搜索词、2—6 字、无生僻字与特殊符号；分类标签全部取自番茄后台实有标签池
  - 简介前三行完成钩子展示、无推广导流信息；封面含书名+作者名、600×800、无外站水印
  - 分卷结构与番茄生命周期对齐（0-2万 / 2-8万 / 8-10万验证期 / 10万+首秀 / 20-50万书测 / 100万书测）
- 通过后：锁定章纲 → 进 写作
- 不通过：回退对应规划环补做
- 平票：交叉提意见 + 综合改稿 + 再投（上限 2 轮，仍平票则人工裁决）

### 写作 · 正文终审
- 位置：写作程序出口（润色开始前）
- 执行处：章内节奏自检
- 投票人：全员 N
- 通过规则：过半通过
- 校验项：
  - 六要素 始显通动成终 齐全且顺序对
  - 四条红线未命中（动≠成/成≠终/始≠显/硬钩不连续两章）
  - 章纲对齐无跑偏
  - 单章字数与断章钩达标
- 番茄专属校验项：
  - 单章 1500—2300 字（日更 4000 拆两章）
  - 开篇 300 字内出冲突；前三章 = 第1章遇麻烦 / 第2章得转机 / 第3章开始反击
  - 每 500—800 字一个转折点；章末钩不与上一章同类型
  - 爽点即时兑现、无憋屈累积；短段落短句、段落长度适配手机端
  - 每章 ≤2 个场景、≤1 个新概念（设定按需投放）
- 通过后：本章正文定稿 → 进 润色
- 不通过：回退对应六要素段重拼
- 平票：交叉提意见 + 综合改稿 + 再投（上限 2 轮，仍平票则人工裁决）

### 润色 · 润色终审
- 位置：润色程序出口（质检开始前）
- 执行处：润色
- 投票人：全员 N
- 通过规则：过半通过
- 校验项：
  - 常规润色 25 条全勾
  - 去 AI 味 15 条全勾
  - 朗读试读 3 条全勾
  - 伏笔没被改丢、人设没被改崩
- 番茄专属校验项：
  - 去 AI 味为番茄合规必过项（机器文本比例须过检，非风格优化）
  - 短段落化与手机端可读性校准；无大段环境描写与长内心戏
  - 章末钩强化：每章最后一句必有钩，且不与上一章同类型
  - 文风跨章/跨卷无突变（番茄对长篇会不定期抽检原创度）
- 通过后：润色定稿 → 进 质检
- 不通过：回退对应润色子项补做（并回查伏笔/人设）
- 平票：交叉提意见 + 综合改稿 + 再投（上限 2 轮，仍平票则人工裁决）

### 质检 · 成书检验
- 位置：质检程序出口（入库前）
- 执行处：成书检验
- 投票人：全员 N + 人终检
- 通过规则：过半通过
- 校验项：
  - 质检终稿验收 19 条全勾
  - 润色三套验收清单全勾
  - 连载连贯性：章间衔接/伏笔状态账/人物状态接续/设定一致
  - 章号与卷结构连续、累计字数与平台更新要求
  - 卷末与全书完结另查：终局收束·烂尾·系列一致性
  - 上架前低级错误检查无问题（错字/标点/格式/名称统一/章号连续）
- 番茄专属校验项：
  - 番茄四类低质红线全过（AI 粗制滥造 / 格式混乱 / 结构失常 / 空洞水文）
  - AI 使用合规为一级必过项（人为主笔；AI 生成段落已改写 ≥70%，无整章直出）
  - 番茄里程碑核对：累计字数与断更风险 / 前 10 章是否已大面积改动 / 20 万字前书名未改 / 书测材料（5 书名+封面）是否备齐
  - 上架三件套与后台信息一致（书名 / 封面含书名+作者名 / 简介无推广导流）；分类标签取自实有池
- 通过后：上架前低级错误检查 → 入库 → 推演下一章 → 进入下章循环
- 不通过：回退返修（表达→润色 / 内容→写作 / 设定→规划），复检通过后重走成书检验
- 平票：交叉提意见 + 综合改稿 + 再投（上限 2 轮，仍平票则人工裁决）


## 六、一致性提醒

三处一致性提醒：① 「分块产出」不等于放弃赛马——关键块（如主角能力代价、力量体系、开篇三章、六要素的动/成段）仍建议多个 AI 同块赛马；非关键块单写即可，省成本。② 「过半通过」是终审投票规则，分块择优仍是『一致好评取之 / 多数票胜出 / 全差退回』，两者不冲突：前者选块内最优，后者判整体能否放行。③ 平票的『交叉提意见』要求双方都给出可执行的块级意见，否则综合改稿无从下手；改稿由 merge_app 执行，不是让原写手各自改。

## 七、赛马记分榜（终审官同步打分统计）

> 引擎：`windows-use/scoreboard.py`；查看：`python orchestrator.py --board [程序]`；解除淘汰：`python scoreboard.py restore <ai>`。

### scoring

- **who**：终审闸的每一位投票官（全员）
- **when**：四程序出口闸：章纲终审 / 正文终审 / 润色终审 / 成书检验
- **what**：本次程序内除自己外每位参战 AI 的综合表现（1—10 分，可带 0.5，必须附一句依据）
- **dimensions**：产出质量（对照本闸验收标准）、返工度（采纳后要返多少工）、稳定性（是否反复踩同类坑）
- **selfRule**：不给自己的产出打分；没参与本程序的 AI 不打分

### adoption

- **marker**：<!--ADOPT: 块ID=产出者-->
- **rule**：拼接者每拼完一块在块尾留采纳标记；记分榜据此统计每 AI 的段落采纳次数，并生成「环节×AI 最佳对照表」

### elimination

- **consecutiveTimes**：3
- **scoreBelow**：6.0
- **rule**：同一程序连续 3 次终审评估垫底（均分最低且 < 6.0）→ 标记淘汰
- **effect**：淘汰后默认不再参战；今日阵容里若强行勾选会告警；人工可解除（scoreboard.py restore <ai>）

### crown

- **minRounds**：2
- **rule**：按程序维度算累计均分排名（采纳次数作同分裁决），跑满 2 轮才有资格；输出冠亚季军与「环节×AI 最佳对照表」
